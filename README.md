# facegate

OpenCV 얼굴 검출 결과에 대한 **순수 로직 품질 게이트**.

이 저장소의 목적은 얼굴 인식 제품이 아니다. Claude Code의 **`unit-test` Skill과 `TDD-guard` Hook이
실제로 동작하는지 검증하기 위한 시험대**다. 기능은 그 검증을 의미 있게 만들 만큼만 실재한다.

## 왜 이 기능인가

TDD 가드를 검증하려면 가드가 **막아야 할 상황과 통과시켜야 할 상황이 모두 자연스럽게 나오는**
작업이 필요하다. 얼굴 검출 후처리가 그렇다.

- 판정 로직은 좌표와 숫자만 다루는 **순수 함수** → 목(mock) 없이 테스트가 나온다
- cv2 호출부는 **단위 테스트가 불가능** → 가드의 가장 어려운 케이스가 저절로 등장한다
- 경계 케이스가 명확하다 (빈 박스, 이미지 밖, 0으로 나누기)

부수 효과로 **테스트 픽스처에 실제 인물 사진이 들어가지 않는다.** 코어의 입력이 이미지가 아니라
좌표이기 때문이다. 생체 데이터가 저장소에 남지 않는다.

## 구조 — 셸과 코어

```
src/facegate/
  geometry.py   코어 · Box, area, iou          (순수)
  quality.py    코어 · 등록 품질 판정            (순수)
  detector.py   셸  · cv2 호출 + 순수 어댑터
tests/
  test_geometry.py  test_quality.py  test_detector.py
```

`detector.py`만 둘로 갈라져 있다. `to_boxes()`는 OpenCV 출력을 우리 타입으로 옮기는 순수
함수라 테스트로 덮여 있고, `detect_faces()`는 cv2를 부르는 얇은 셸이라 덮지 않는다.
**이 분리는 가드가 강제한 결과다** — 아래 참조.

## 실행

```bash
python -m pip install pytest opencv-python
python -m pytest
```

## 검증된 가드 동작

작업 중 실제로 관찰한 것만 적는다.

| # | 상황 | 결과 |
|---|---|---|
| 1 | 테스트 실행 기록 없이 구현 파일 수정 | 차단 ✓ |
| 2 | pytest 수집 에러(`1 error`) | RED으로 정확히 파싱 ✓ |
| 3 | RED 상태에서 구현 수정 | 허용 ✓ |
| 4 | GREEN 상태에서 새 선언 추가 | 차단, 선언 개수까지 셈 ✓ |
| 5 | 테스트 11개 한 번에 추가 | 차단 (one-test-at-a-time) ✓ |
| 6 | 테스트 파일 수정 | 항상 허용 ✓ |
| 7 | `.toml` / `.md` / `.gitignore` | IGNORE로 통과 ✓ |
| 8 | `ignore` 파일에 등록한 경로 | 통과 ✓ |

특히 4번이 핵심이다. 순진한 가드는 GREEN에서 모든 구현 수정을 막아 리팩터를 불가능하게
만들거나, 반대로 전부 허용해 무력해진다. 이 가드는 **새 선언이 늘어나는지**로 둘을 가른다.

## 발견된 한계

1. **상태 파일이 프로젝트가 아니라 cwd 기준이다.**
   상태는 `<cwd>/.claude/tdd-guard/state`에 쌓인다. Claude Code의 작업 디렉터리가 홈이면
   모든 프로젝트가 상태 파일 하나를 공유한다. 실제로 이 작업의 상태는
   `C:\project\claude_project`가 아니라 `C:\Users\user`에 기록됐다.
   `ignore` 목록도 같은 이유로 전역이므로 패턴을 좁게 적어야 한다.

2. **한 번도 실패한 적 없는 테스트를 잡지 못한다.**
   GREEN 상태에서 추가한 테스트가 곧바로 통과해도 가드는 침묵한다. 실제로 이 작업 중
   `iou`의 0-나누기 테스트를 잘못 써서 즉시 통과했고, 가드가 아니라 사람이 발견했다.
   (`unit-test` Skill의 절대 규칙 2가 다루는 영역이지만, 훅으로는 강제되지 않는다.)

3. **테스트 불가능한 셸에 대한 정책이 없다.**
   cv2 호출부처럼 단위 테스트가 원천적으로 불가능한 코드도 IMPL로 분류돼 차단된다.
   현재는 `ignore` 파일에 수동 등록하는 것이 유일한 해법이다.
   가드가 설계를 개선하는 방향으로 압력을 준 것은 사실이지만(셸/코어 분리), 마지막 한 줄은
   결국 예외 처리로 넘어간다.
